# Token reconciliation - what DGA declares vs what this kit ships

Generated by `harvest/reconcile-tokens.py` against DGA stylesheet build **PDaQ7SHU**.
Regenerate with `python3 harvest/reconcile-tokens.py --write`. Do not edit by hand.

`tokens.json` carries **303** values plus **67** dark, out of the custom properties
counted below. For two releases the kit explained that difference away as aliasing.
This file is the reconciliation that disproved it, regenerated from the live
stylesheet.

**Matching is by resolved value, not by name.** A declaration resolving to a literal
already present in `tokens.json` carries no value the kit is missing. That is the claim
being tested. It does **not** establish that each dropped var is a semantic duplicate -
two unrelated roles can both be `8px`.

## Verdict

**951 of 1467** declarations resolve to a value `tokens.json` already carries. **516** do
not, so the "all aliases" reading of the gap is **wrong** and is retracted.

| The 516 that do not reconcile | Count |
|---|---|
| Generic UI-kit palette DGA ships but does not publish as a DGA token | 276 |
| **DGA-namespaced values this kit simply does not hold** | **240** |

The first group is a defensible exclusion — DGA's stylesheet carries the whole upstream
Untitled-UI ramp (blue, cyan, fuchsia, indigo, moss, orange, pink, purple, red, teal,
violet, yellow, and seven separate grey ramps) and the published system names 11 families.
It was never *stated* as an exclusion, which is the actual defect. The second group is a
real coverage gap.
