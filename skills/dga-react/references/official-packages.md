# The official DGA packages

**This changes the build plan.** DGA ships an official, actively-maintained component library.
Do not write DGA components from scratch, and do not use the community `dga-ui-react` package.

**Source:** https://design.dga.gov.sa/developing · retrieved 2026-08-26

> To integrate Platforms Code UI React into your project… `npm install platformscode-new-react@latest`
> — /developing

## What ships

| Package | Version | What it is |
|---|---|---|
| `platformscode-new-react` | 0.1.45 (2026-08-23) | Official React wrappers — **this is the one to install** |
| `@platformscode/core` | 0.0.52 | The underlying Stencil web-component library, 175 components |
| `@platformscode/react` | 0.1.17 | Older/parallel React binding — confirm with DGA which is current |
| `platformscode-react` | 0.1.0 | Appears abandoned at 0.1.0 |

Architecture is Stencil web components with framework wrappers generated by
`@stencil/react-output-target`. Every custom element is prefixed `dga-`.

Published three days before this harvest — actively maintained.

## What you get for free

**175 components**, including the UI-shell pieces a government service needs and that most
third-party kits lack: `dga-header`, `dga-nav-header` (with sub-menu columns and links),
`dga-second-nav-header`, `dga-footer`, `dga-drawer`, `dga-slideout-menu`, `dga-table-of-content`.

Plus `dga-data-table`, `dga-datepicker`, `dga-file-upload`, `dga-digital-signature`,
`dga-filteration`, `dga-progress-indicator`, `dga-status-tag`, `dga-metric`, `dga-apex-chart`,
and the full form set.

**Icons are bundled.** DGA states the Platforms Code icon set is "included by default in all
DGA packages… with no separate installation required."

**RTL is handled.** 48 components carry `[dir=rtl]` styling — the standard attribute-driven
approach, e.g. pagination arrows are transformed under `[dir=rtl]`. Set `dir="rtl"` on `<html>`
server-side and the library follows.

## ⚠️ What you do NOT get — verified gaps

### 1 · No Hijri calendar. At all.

Searched the entire published package for `hijri`, `islamic`, `umalqura`, `umm-al-qura`. The
only matches anywhere are a `calendar-03` **icon name** and a code comment about calendar grid
days. `dga-datepicker`, `dga-date-field`, `dga-date-cell` and `month-navigator` are
Gregorian-only.

For a Saudi government service this is a material gap. **The project has to supply Hijri
support itself** — see `../../dga-rtl-i18n/references/formats.md` for the
`Intl.DateTimeFormat('ar-SA-u-ca-islamic-umalqura', …)` approach. Decide early whether you
wrap `dga-datepicker` or replace it, because it affects every date field in the product.

Raise it with DS-DGA@dga.gov.sa — if it's on their roadmap, wrapping beats replacing.

### 2 · Almost no locale plumbing

Exactly one component references `locale`. Translation, number formatting and pluralisation are
entirely the consuming app's job. `dga-rtl-i18n` covers this.

### 3 · Versioning is pre-1.0

`@platformscode/core` at `0.0.52`, React wrappers at `0.1.45`, across 143 published versions.
Pin exact versions and read the changelog before every bump — pre-1.0 semver gives you no
breaking-change guarantee.

Note also that `@platformscode/core`'s manifest still carries `"description": "Stencil Component
Starter"` and points its `repository` at `ionic-team/stencil-component-starter` — scaffolding
metadata that was never updated. Cosmetic, but it means you cannot find the real source repo
from npm; ask DGA for it.

## Decision for this project

1. **Install `platformscode-new-react`.** Treat it as the component layer.
2. **`dga-react`'s job is the gap layer, not a component library** — Hijri dates, i18n wiring,
   token enforcement, and any entity-specific composition on top.
3. **Do not adopt `dga-ui-react`** (the community package). Its palette does match DGA's real
   tokens, but it is an unofficial reimplementation with no UI shell and no Hijri support
   either — it offers nothing the official package doesn't, and it carries drift risk.
